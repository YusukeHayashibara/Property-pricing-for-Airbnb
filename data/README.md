# data/

Raw, interim, processed and external data are **not versioned** (see `.gitignore`); only
`data/reference/` is. This page says where each file comes from and what regenerates it.

| Path | Content | Origin |
|---|---|---|
| `raw/Airbnb/` | `listings.csv`, `calendar.csv`, `reviews.csv`, `neighbourhoods.csv` | Inside Airbnb, São Paulo, scrape of 14–16 Jun 2026 |
| `raw/IPTU-SP/iptu_2025.zip` | IPTU 2025 register (~3.8M rows) | Prefeitura de São Paulo |
| `raw/ISP/*.csv` | SSP-SP monthly crime files, Jan–Dec 2025 | SSP-SP (the folder keeps the old name "ISP") |
| `processed/ISP/dados_criminais_sao_paulo_2025.csv` | consolidated crime counts by DP, crime type and month (2024 and 2025) | `notebooks/crime_analysis.ipynb`. Some machines name the folder `SSP/`; the aggregation notebook and the scripts accept either |
| `processed/IPTU-SP/iptu_2025_clean.zip` | cleaned IPTU | `notebooks/iptu_analysis.ipynb` (some machines have `processed/IPTU/iptu_2025_clean.csv`) |
| `processed/Airbnb/listings_clean.csv` | cleaned listings | `notebooks/airbnb_analysis.ipynb` |
| `external/distrito_municipal.geojson`, `quadra_fiscal.gpkg` | distrito polygons (96) and fiscal blocks (64k) | GeoSampa WFS (`geoportal:distrito_municipal`, `geoportal:quadra_fiscal`) |
| `external/quadra_to_distrito.csv` | fiscal block → distrito lookup | spatial aggregation study (`notebooks/spatial_aggregation_study.ipynb`) |
| `external/dp_to_distrito.csv` | first-draft DP → distrito (geocoded) | spatial aggregation study. **Superseded** by `reference/dp_distrito_crosswalk.csv` |
| `external/dp_distrito_crosswalk.csv` | crosswalk as used in the last build | generated by `notebooks/aggregation.ipynb` |
| `external/poi_by_distrito*.csv` | OpenStreetMap POIs by distrito | generated by `notebooks/aggregation.ipynb` (Overpass), placeholder for Google Places |

| `processed/listings_aggregated.csv` | 1 row per listing, 192 columns | `notebooks/aggregation.ipynb` |
| `processed/distrito_features.csv` | 1 row per distrito, 113 columns | `notebooks/aggregation.ipynb` |

| `raw/Airbnb/photos_manifest.csv` | one row per downloaded cover: url, status, error, date | `scripts/fetch_airbnb_covers.py` |

| `raw/StreetView/{id}_{heading}.jpg` | Google Street View, 4 headings (0/90/180/270), 640×640, only "© Google" panoramas | `python scripts/fetch_streetview.py --ids-arquivo …` (needs `GOOGLE_MAPS_API_KEY` in `.env`; billed per image) |

| `interim/amostra_reviews.csv` · `amostra_reviews_ids.txt` | the 200-listing stratified sample (group, type) · its ids, one per line | `foto_vs_review.ipynb` (`src/amostra_reviews.py`); the `.txt` feeds `fetch_streetview.py` |

| `processed/Airbnb/amostra_clusters.csv` | per listing: cluster and UMAP coordinates for covers and Street View, price, adjusted price | `notebooks/imageAnalysis/clusters_amostra.ipynb` |
| `processed/Airbnb/amostra_clip_*.npz` · `amostra_dino*_streetview.npz` | image embedding caches (CLIP, DINOv2), invalidated when an image file changes | `clusters_amostra.ipynb` |

## Rebuilding the aggregated tables

1. Put the raw files above in `raw/` and run the EDA notebooks that write `processed/`.
2. `python scripts/fetch_population_distrito.py` (needs internet).
3. Run `notebooks/aggregation.ipynb` top to bottom. It writes `listings_aggregated.csv` and
   `distrito_features.csv`. Column dictionary: `docs/data-dictionary-aggregation.md`.

Downstream notebooks (`eda_agregado`, `eda_espacial`, image and text) read these CSVs, so rerun the
aggregation after pulling changes that touch it.

## Rebuilding the image sample

1. Run `notebooks/imageAnalysis/foto_vs_review.ipynb`: it draws the stratified sample, downloads the
   covers (replacing listings whose photo returns 404) and writes `interim/amostra_reviews*.csv`.
2. `python scripts/fetch_streetview.py --ids-arquivo data/interim/amostra_reviews_ids.txt` (and
   `--revisar` after any change in the panorama filter). The metadata lookup is free; each image is
   billed, capped by `--max-imagens` per day.
3. Run `notebooks/imageAnalysis/clusters_amostra.ipynb`.

Coordinates in Inside Airbnb are shifted by up to ~150 m, so Street View shows the surroundings of a
listing, not its facade.
